# headroom 保留轮数对照：0～4 轮

2026-09-13，在计量代码 `08ecb2f` 上比较 `retainRecentTurns=4/3/2/1/0`。结论是将 **layered 默认值设为 1 个完整历史轮次，另加当前活动轮次**。选择标准为：关键约束、答案、可见上下文事实和恢复检查不相对四轮退步，再选择累计输入最低的配置。此结论适用于本次离线历史，不代表真实模型任务成功率的最优值。

`legacy` 的默认值仍为 4；显式配置优先，包括 0。0 表示只保护当前轮次，绝不表示压缩正在进行的当前轮次。需求、修正、未知内容和失败诊断的保护规则保持原有要求。

## 实验设置与证据

- 原有 11 份 fixture × A/B/C/D × 五档轮数 × 两种检索策略，共 **440 条**回放记录。计量代码、fixture、8192 上下文、1024 输出预留、4096 记忆上限、15% 记忆比例、70% 触发和 55% 目标固定；RTK 为 512 token / 40ms / 512 字节。每组四阶段，每阶段两个真实 transform，包含计划发布前的第一次输入。
- query-only 返回问题相关片段；eager-recovery 继续分页读取全部命中文档。两种策略都计入检索及其进入后续上下文的重复输入，外层检索限额为 8192 token / 32768 字节。
- 使用既有 24 份 headroom 专用历史交叉检查：八类场景 × 50/200/1000 轮 × 五档保留轮数，共 **120 条**记录，RTK 关闭。四阶段、每阶段两次 transform，再执行查询及首命中展开。
- 总计 **560 条**记录，顺序执行，每次使用隔离数据目录和真实插件 runtime、sidecar。LLM 摘要关闭，外部模型调用为 **0**。未修改 fixture 或放宽原有保护规则。
- 原有消融使用 `o200k_base`；专用历史使用 `ceil(UTF-16 字符数/4)` 估算，分别解释，不合并成统一 token 总数。CPU 与 RSS 是本机采样观察，不作为账单或加速承诺。

所有原始报告、fixture SHA-256、报告 SHA-256、参数与门禁结果见[运行清单](../packages/eval/retention-results/manifest.json)。四轮对照完整复现此前正式输入 369,220 和压力输入 467,608，A/B 在十次消融中均为 582,501 / 464,781。[原四轮记录](headroom-ablation.md)和[legacy 冻结基线](../packages/eval/baseline.json)继续保留。

保留 0 轮虽然也通过原有 query-only 门禁，但在 `long-session` 的 C/D 中额外移出了三条可见事实：`new timeout handling`、`new protocol version handling`、`budget increased for large outputs`。C 的事实数从 104/104 降为 101/104，D 从 102/104 降为 99/104。原文可恢复、现有十个答案仍能通过，不能据此说原文丢失；但这使模型立即可见的信息减少。0 相对 1 仅再降低约 **2.10%** 组合输入，因此按预定的不退步标准采用 1。

1/2/3 与四轮保留的事实身份也一致，并非仅数量相同。B/D 原有两个事实缺失与本次调参无关，未被重新归类为通过。

只有四轮 eager 的 `combinedNetInput` 低于 20% 门槛，其余九份消融报告均通过绝对门禁；该历史压力组失败如实保留。

## 实现与复现

默认值由 contracts 中的策略表统一提供，插件配置、wire 参数解析和纯 layered 规划器一致采用 `layered=1 / legacy=4`；显式值使用空值合并，0 不会被默认值覆盖。

每次发布或重放分层视图时，还会依据当前宿主轮次重新检查操作是否触碰受保护尾部。例如曾经以 0 轮生成的视图，在重启改为 1 或 4 轮后，不能仅凭旧来源摘要仍匹配就继续应用。原文与节点保留，冲突活动视图清理后按当前配置重新规划；旧四轮视图符合一轮的保护要求，可以继续复用。

历史离线回放和历史实机评测显式固定四轮，避免生产默认值改变旧结果的复现含义。`eval` 的默认保留数仍为 4；采用当前正式方案的实验命令须显式传 1。实机报告也记录固定保留数，未运行新的真实模型对照。

```sh
# 重跑全部五档消融及专用历史；更新 retention-results 中的实验文件
bun run eval:retention

# 单独复现采用的一轮方案，结果写入临时目录
bun run eval --invariants --headroom-strategy layered --retain-recent-turns 1 \
  --retrieval-strategy query-only --report-path /tmp/headroom-retain-1-query.json
bun run eval --invariants --headroom-strategy layered --retain-recent-turns 1 \
  --retrieval-strategy eager-recovery --report-path /tmp/headroom-retain-1-eager.json

# 原基线继续按旧版四轮检查
bun run eval --check --headroom-strategy legacy --retain-recent-turns 4 --skip-latency \
  --report-path /tmp/headroom-legacy-regression.json
```

实现、实验驱动和文档由 AI 辅助完成。结果来自实际离线运行，不能替代真实模型对 0～4 轮的任务完成率、缓存 usage 和总费用比较。
