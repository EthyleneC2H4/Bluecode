# headroom 分层实现与验收记录

本轮实现位于 `codex/headroom-layered`，起点为 `main@62589ac`。RTK 算法保持原版本；headroom 新增有预算的分层规则路径、操作式视图、原文恢复和可选后台摘要。默认策略暂保留 `legacy`，摘要默认关闭。配置与操作说明见 [使用指南](headroom-layered.md)。

## 已实现的边界

- 原文经 CAS 确认后才替换；需求、明确修正、含义不明确的材料、未知 part、运行中工具与近期完整轮次继续保护。安全区间可跨过保护内容。
- 任务状态绑定来源与版本，历史记忆受独立预算约束；不可变叶子和父节点保存展开关系，缓存复用未变内容。源快照验证仍需线性扫描。
- wire v3 支持范围、工具输出、明确材料范围三类原子操作。每次 fresh-array 应用检查来源、摘要和 epoch；上游 compaction 与真实内容变更使候选失效。
- SQLite FTS5 返回短命中卡片，原文、历史与节点可分页展开；最终 JSON 同时受 token 估算和字节预算约束，并保持项目／会话隔离。
- 独立摘要适配器不经过 Agent Loop；规则计划先返回，后台候选经最新宿主校验后发布。超时、格式错误、来源错误、膨胀和配置不一致继续使用规则结果。额度预约与消费跨重启保存。

真实 OpenCode 接线测试还修复了两处模拟回放不易暴露的问题：活动 assistant 的流式增长不应使历史规则计划失效；OpenCode 每步更新最后一条用户消息的 `summary.diffs` 时，只有能够证明模型可见内容和 epoch 未变的完整 metadata 更新才可忽略。用户文本或 part 的真实变更仍会失效。

## 离线结果

机器可读记录为 [24 组离线回放及工程回放](../packages/eval/headroom-layered-results.json)。这些数字使用 `ceil(UTF-16 字符数 / 4)` 估算，**不是模型 provider usage 或账单**。回放调用生产插件 runtime 与实际启动的 daemon，没有调用外部 LLM。

每组在四个历史前缀各调用两次 transform，计入规则计划尚未发布的第一次输入；随后执行查询及首命中展开，把检索内容进入后续上下文的重复输入一起计量。不是每个历史轮次都调用一次模型。原文完整性检查单独计量，不加入模型输入。

| 项目 | 结果 | 解释 |
|---|---:|---|
| 新规则版完成 | 24 / 24 | 8 类场景各 50、200、1000 轮 |
| 新旧可比较组 | 17 / 24 | 7 组旧版 1000 轮回放达到 10 秒 RPC 超时，标记未完成并排除收益计算 |
| 可比较组累计输入 | 15,810,622 → 4,428,698 | 合计降低 71.99%，不是全部 24 组或真实任务的收益承诺 |

原有 `packages/eval/baseline.json` 未覆盖。新的 engineering-replay 口径与旧基线的固定检索回放不同，不能把两个协议的绝对 token 数直接串成收益曲线。

增量计量示例：`unique-code-1000` 四个检查点累计扫描 5000 条消息，实际分析 2000 条、命中分析缓存 3000 条。daemon 累计 CPU 4.94 秒，采样峰值 RSS 约 335 MiB，四次规划服务时间合计约 4.32 秒。这说明内容分析得到复用，同时也表明大历史的快照、节点和存储工作仍有成本；RSS 是采样峰值，不是操作系统高水位。

另有独立的 20 代真实归档测试：在第 2、5、20 代重启存储，逐个恢复此前所有已确认的原文哈希并逐字节比较，而不仅检查一个选定来源；同时检查跨 namespace 拒绝。离线矩阵中的“20 个检查点”不表示 20 层摘要树。

## 真实模型对照

正式记录见 [72 次实机任务结果](../packages/eval/headroom-live-results.json)，运行代码固定为 `0e4f4db`。主模型固定为 `opencode/mimo-v2.5-free`，通过实际 OpenCode 1.18.23 调用，金额预算为 0，不允许付费模型回退。密钥由环境变量传入，不进入仓库、报告或命令行参数。

确定性导入的 14 轮材料是评测 fixture；随后由真实模型完成 12 个小型任务，覆盖缺陷、跨文件、测试修复和长日志分析，每组三策略各重复两次。RTK 统一关闭，宿主、权限和初始代码固定。任务通过、约束、四类续接探针、压缩实际应用、缓存 usage 和摘要终态分别记录。

实机采用压力配置：宿主输入窗口显式设为 40,000、输出上限 2,048，历史记忆上限为 128，以便短任务中的导入历史触发压缩与增强准备；这不是默认 4,096 记忆预算的实机效果。代理统一缓冲响应以计量 usage，四个任务可并行；耗时不能直接等同于无代理的生产延迟。`OpenCode tokens.input` 不含缓存，累计完整输入按 `input + cacheRead + cacheWrite` 计算，并单列未命中缓存的输入。

正式运行前的探索暴露了评测器漏洞：测试修复组可能通过删除测试获得误判，字符估算不是可靠的输入预约上界，直属进程退出也不保证后代释放输出管道。因此探索数据不计入正式通过率；评测器增加原验证器不变检查、修复测试的 mutation 检查、有界进程组清理以及独立摘要 usage／终态记录。续接探针同时记录严格原句格式与完整证据存在，避免把正确原句后附带其他约束误报为遗忘。

修复后的首次试运行仍受原 180 秒任务时限影响：宿主依赖安装因用户 npm 缓存权限失败等待约 71 秒，实际免费模型请求另需约 13–60 秒。该批超时不解释为模型质量回归，也不并入正式通过率。正式协议改用隔离的 npm 缓存与明确 600 秒任务时限，调用次数和免费模型限制保持不变。

Zen 免费接口要求真实 OpenCode 会话。普通独立摘要 HTTP 适配器收到的拒绝须记为增强不可用或规则回退；不能将该组称作已验证的语义摘要收益，也不伪造宿主会话标识绕过服务限制。

### 完整实机结果

三组各完成 24 次主任务，代码测试与关键约束均为 24 / 24，主模型 usage 完整。规则版与增强尝试组的规则压缩均在 24 / 24 次任务中实际应用；旧版在本压力历史中没有发布正收益视图。

|---|---:|---:|---:|
| 主任务通过／关键约束通过 | 24 / 24 | 24 / 24 | 24 / 24 |
| 主模型请求 | 144 | 144 | 136 |

规则版累计完整输入降低 **36.71%**，计入输出后的主模型总 token 降低 **36.44%**。24 个配对均降低完整输入，范围 3.69%–53.09%，19 个配对达到降低 25%。与此同时，未命中缓存的输入增加 **29.62%**，输出增加 **13.58%**，工具调用从 163 增至 168；不能把完整输入的下降直接解释为付费模型账单同比下降。耗时中位数差异很小，且受代理、并发和远端排队影响，不据此承诺生产加速。

自动续接探针按“事实／文件／下一步／理由”计数：旧版为 **23 / 22 / 23 / 23**，规则版为 **24 / 24 / 24 / 24**，增强尝试组为 **24 / 24 / 24 / 23**，各项分母为 24。原句严格格式分数另见 JSON。旧版一例未写 handoff，一例只列配置文件、漏列主文件；增强尝试组的一例理由实际仍包含正确原句，但混入 `Rationale:` 标签和其他字段，因此自动字段匹配未通过。保留原评分，不把这个格式偏差解释为事实丢失。

增强服务共尝试 **32 次**：31 次为 HTTP 400 `MissingSessionID`，1 次为传输失败；实际输入、输出 usage 未知。候选观测为 22 条拒绝、10 条结束时仍 queued，**没有增强候选实际应用**。因此第三列仅证明规则退化路径仍能完成主任务，不能与规则版的随机运行差异归因于 LLM 摘要。

总计 456 次请求，其中 424 次主模型请求均为 HTTP 200。输入预约 51,042,395 / 80,000,000，输出预约 901,120 / 1,474,560，请求上限 720；没有预算耗尽或观测到的额度违反。因摘要 usage 未知，含摘要的实际总消费保持 `null`，整个增强效果对照标记 `incomplete: true`，CLI 按设计退出 2。**72 次主任务已完成，并不等于 LLM 增强效果通过验收。**

### 默认策略决定

本轮交付可显式启用的分层规则版；默认仍为 `legacy`，LLM 增强继续关闭。原因是：实机验证采用 128 记忆预算压力配置，尚不能作为默认 4,096 配置的完整实机验收；缓存外输入上升使付费净成本不能由本次免费调用推出；重复输出和部分自然检索的离线回归仍需保留。规则版已显示可复现的上下文缩减和任务保持，默认切换门槛尚未全部验证。

12 个小任务各重复两次的样本不足以估计大型项目的成功率或稳定收益区间。这里报告每项观察与反例，不将本轮压力测提升为生产效果承诺，也不将“引入 LLM”作为完成标准。

## 回归与审查

在 `0e4f4db` 执行 `bun run verify`：578 项测试、11311 条断言、84 个测试文件全部通过；七个包的类型检查、依赖方向检查及宿主 bundle 不引入 SQLite 的边界检查通过。测试运行时间 64.44 秒。原冻结基线检查也通过，未修改旧基线数字。最终整分支审查发现的持久视图策略回退问题已修复并通过定向复审；实机评测器及后续时限／缓存修正也分别通过审查。本条只证明实现与回归状态，不代替实际收益验收。

## 实施中的裁定

1. 在离线与实机门槛全部满足前保留 `legacy` 默认值。代价是延后默认采用新算法，避免把未验证收益当作切换依据。
2. 依据用户授权只用 Zen 免费模型，另设明确请求数和 token 预约上限。代价是免费接口限制可能使增强对照无法完成，不改用收费服务。
3. 离线评测由独立工作者负责，实机入口与接线由协调者负责；接口偏差由最终集成解决。代价是交界处可能需要返工。
4. 实机主任务可并行运行四个相互隔离的目录，摘要服务自己的并发限制保持不变。代价是本机资源竞争限制了耗时比较的解释范围。
5. 正式评测将旧字符估算预约改为完整 UTF-8 请求字节与包装余量的保守预约，单独设置 80,000,000 输入预约、720 次请求和 1,474,560 输出预约上限；金额预算仍为 0。代价是预约量可能明显高于实际 token，不能把新旧预约数作为模型消费比较。
6. 现有持久格式无法证明已增强视图的完整 provider 配置一致，重启时清除其活动指针并按当前配置重建，不扩充 wire 格式。代价是可能少复用一次摘要，增加有界的准备工作；原文与节点不删除。
7. 将单任务时限从 180 秒改为显式 600 秒，以覆盖已观察到的免费接口延迟；每任务仍最多 8 次请求。代价是故障报告可能更慢，模型调用许可不增加。

本记录与代码由 AI 辅助开发和审查；数值来自提交的实验记录及可执行验证，不把生成的测试材料当作真实用户生产会话。
