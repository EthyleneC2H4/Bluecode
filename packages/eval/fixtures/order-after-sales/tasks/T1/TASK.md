# T1 创建订单与重复提交

角色：你是订单服务开发者。用户可能因网络超时同时重试创建订单。实现 `src/operations.ts` 的 `createOrder`，保持现有 HTTP 接口与数据结构。

运行：`bun test`，`bun run start`；`POST /_reset` 恢复固定种子，`GET /state` 查看本地状态。请求为 `POST /orders`，JSON 为 `{ "sku": "SKU-1", "quantity": 1 }`，请求头 `Idempotency-Key` 必填。成功返回 201 和订单对象。

业务契约：商品单价只能取服务端 `state.prices`，金额为整数分；忽略客户端传入的价格。数量必须是正整数，商品必须存在，库存不足时拒绝且库存不能变为负数。相同幂等键和相同业务请求返回第一次的相同订单与状态，不重复扣库存；同键不同请求返回 409。不同键的并发购买不能超卖。非法请求返回 400，未知商品返回 404，库存不足返回 409。订单从 `PENDING` 开始，ID 由本地递增序号产生。失败不得改变任何状态。

简化：只有单 SKU 订单、固定价格、无优惠、无支付网关、无物流和商家系统。当前服务在一个进程内串行提交事务；不要接入外部服务。公开样例：一次购买 SKU-1 数量 1 的金额为 1250 分，初始库存 2 变为 1。
