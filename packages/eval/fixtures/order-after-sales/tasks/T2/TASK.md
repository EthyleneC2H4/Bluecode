# T2 取消订单与库存释放

角色：你是订单服务开发者。用户与客服可能重复发起取消请求。实现 `src/operations.ts` 的 `cancelOrder`，保持现有 HTTP 接口与数据结构。

运行：`bun test`，`bun run start`；`POST /_reset` 恢复固定种子，`GET /state` 查看本地状态。请求为 `POST /orders/{id}/cancel`，JSON 为 `{}`。成功返回 200 和取消后的订单对象。

业务契约：仅 `PENDING` 订单可取消。取消时释放原订单数量到对应 SKU 的库存，并将状态改为 `CANCELED`，两项变更必须同成同败。再次取消同一已取消订单返回相同订单，不再次释放。`PAID` 或 `SHIPPED` 不能按未支付取消，返回 409；未知 ID 返回 404。失败不得改变状态。

简化：支付状态由种子模拟，无支付网关或真实退款；库存只在本地单进程事务中修改。公开样例：取消 `o-pending` 后 SKU-1 库存从 1 变为 2，再取消仍为 2。
