# T3 部分退款与累计约束

角色：你是售后服务开发者。已支付订单可能发生多次部分退款，用户会重试同一次请求。实现 `src/operations.ts` 的 `refundOrder`，保持现有 HTTP 接口与数据结构。

运行：`bun test`，`bun run start`；`POST /_reset` 恢复固定种子，`GET /state` 查看本地状态。请求为 `POST /orders/{id}/refunds`，JSON 为 `{ "quantity": 1, "amountCents": 1250 }`，请求头 `Idempotency-Key` 必填。成功返回 201 和退款记录。

业务契约：仅 `PAID` 订单可退，`PENDING`、`CANCELED`、`SHIPPED` 均返回 409。数量及金额必须是正整数，金额必须严格等于本订单 `unitPriceCents × quantity`（本题无优惠），累计数量不超过原购买数量，累计金额不超过原实付金额。相同订单、相同幂等键和相同请求返回第一次的相同退款记录；同键不同请求返回 409。失败不增加累计退款数量、金额、退款记录或序号。未知订单返回 404，非法请求返回 400，超过可退范围返回 409。

简化：模拟支付已成功，无真实支付网关、优惠分摊和退货物流。公开样例：`o-paid` 购买 3 件，每件 1250 分；第一次退款 1 件 1250 分后，最多还能退 2 件 2500 分。
